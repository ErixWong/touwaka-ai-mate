# Archive 归档入口

本目录存放已完成使命、被替代或仅保留追溯价值的历史设计材料。

## 目录定位

- `archive/` 中的内容默认不作为当前实现依据。
- 保留这些文档的目的，是为了说明某个设计为什么被放弃、被替代或已经完成历史使命。
- 如果一个设计仍与当前实现直接相关，它就不应该留在本目录。

## 使用规则

- 引用归档文档时，应明确标注“历史参考”。
- 如果某文档只剩背景价值，应优先从主索引移除，避免误导读者把它当现行方案。
- 若归档文档重新变得重要，应迁回 `core/`、`topics/` 或 `../../apps/`（若属于 App 平台现行实现），而不是在归档目录内继续迭代。

## 后续治理建议

1. 继续检查归档文档顶部是否明确说明“为什么归档”
2. 对与当前结构冲突较大的历史表述，保留原意但补足新的导航入口
3. 避免再向 `archive/` 放入“还在活跃推进但暂时没归属”的内容
